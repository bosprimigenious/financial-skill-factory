# 交付接口

`run(input_dir, cut_id, prior_state=None)` 返回且仅返回 `order_control`、`allocation_fees`、`correction_journal`、`state`，整体可直接 JSON 序列化。

`prior_state` 只可作为性能提示。传入任何本引擎先前返回的状态，结果必须与从原始材料完整重放严格一致；允许用较晚状态查询较早切点。

## order_control

按 `order_id` 升序，每个截至业务截止时点出现过的订单一行：

- `order_id`
- `received_at`：统一时钟 ISO 字符串；不可确定时为空字符串
- `status`：`FEEABLE`、规程第 11 节状态，或 `NO_ACTIVE_FILL`
- `active_fill_count`
- `active_quantity`
- `evidence_ids`

## allocation_fees

仅输出可计费分配，按 `fill effective_at`、`fill_id`、`allocation_id` 升序：

- `allocation_id`、`fill_id`、`order_id`、`account_id`
- `notional_cny_minor`
- `commission_minor`
- `exchange_minor`
- `stamp_minor`
- `rebate_minor`
- `total_fee_minor`
- `evidence_ids`

## correction_journal

按 `journal_key` 升序：

- `journal_key`
- `allocation_id`
- `fee_type`：`COMMISSION`、`EXCHANGE`、`STAMP`、`REBATE`
- `expected_minor`
- `booked_minor`
- `difference_minor`：请求冲突时为空字符串
- `status`：`PROPOSED` 或 `REQUEST_CONFLICT`
- `evidence_ids`

没有已记账行也必须与零比较。负费用按负数记账。已有效办理的人工请求不输出。

## state

至少包含：`schema_version` 固定为 1、`cut_id`、`knowledge_at`、`business_through`、`raw_facts`。`raw_facts` 必须足以支持任意切点重放，不得包含绝对路径、运行时刻或随机标识。

所有数组顺序稳定，证据标识排序去重。相同输入的返回值逐字节等价。
