# 组合分析接口

## 1. 范围

单分群因果输出回答试验证据能否直接授权变价。组合分析使用治理参数中的规划系数和联合情景，回答管理层在证据修复后应优先评审哪组联动动作。两者不得互相替代：数据阻断或因果不足仍维持发布失败关闭，但不得跳过组合目录、完全信息基准和遗憾计算。

对三个分群各取 `01_定价与发布控制.xlsx` 中允许的动作，做笛卡尔积。应恰有 `15 × 15 × 9 = 2025` 个联合策略。策略在观察世界前一次选定，不得按世界分支。

## 2. 联合世界

按 `world_id` 读取 27 行。`raw_probability` 统一归一为 `probability`，不得假定输入之和等于 1。把 `16_组合治理参数.json` 三条状态轴展开到每个世界。

`joint_worlds.csv` 字段：

```text
world_id,macro_state,competition_state,collection_state,raw_probability,probability,demand_multiplier,activation_shift,own_price_scale,cross_price_scale,collection_delay_days
```

## 3. 世界内分群结果

对分群 `i`，令 `j` 遍历其余分群：

```text
r_i = baseline_rate_i + fee_delta_i
q_i = ln(r_i / baseline_rate_i)
u_i = term_delta_i / 30
cross_i = sum(gamma_i,j * cross_price_scale * q_j)

conversion_i = clip(
  baseline_conversion_i
  + activation_shift
  + activation_price_i * own_price_scale * q_i
  + activation_term_i * u_i,
  0, 1)

monthly_tpv_i = leads_i * baseline_tpv_per_eligible_i
  * demand_multiplier
  * exp(volume_price_i * own_price_scale * q_i
        + volume_term_i * u_i
        + cross_i)

annual_contribution_i = 12 * (
  monthly_tpv_i * (r_i-variable_cost_i) / 10000
  - leads_i * conversion_i * activation_cost_i)

baseline_world_contribution_i = 12 * (
  leads_i * baseline_tpv_per_eligible_i * demand_multiplier
  * (baseline_rate_i-variable_cost_i) / 10000
  - leads_i * clip(baseline_conversion_i+activation_shift,0,1)
  * activation_cost_i)

contribution_delta_i = annual_contribution_i-baseline_world_contribution_i
annual_fee_revenue_i = 12 * monthly_tpv_i * r_i / 10000
cash_release_i = annual_fee_revenue_i
  * (-term_delta_i-collection_delay_days) / 365
annual_activations_i = 12 * leads_i * conversion_i
```

不得把单分群 IV 系数带入组合公式。迁移项只使用其他分群的费率对数变化，不使用本分群自身变化。

## 4. 世界可行性、短缺与得分

每个世界汇总三个分群。依次计算：

```text
conversion_violation_pp = sum(max(0,
  baseline_conversion_i + minimum_conversion_change_pp - conversion_i))
activation_excess = max(0,
  sum(annual_activations_i)-annual_activation_capacity)
contribution_shortfall = max(0,-sum(contribution_delta_i))
cash_shortfall = max(0,
  cash_release_floor_cny-sum(cash_release_i))

shortfall = contribution_shortfall
  + cash_shortfall
  + activation_excess_penalty_cny * activation_excess
  + conversion_violation_penalty_cny * conversion_violation_pp

world_feasible = shortfall <= comparison_tolerance
world_score = sum(contribution_delta_i)
  + capital_value_rate * sum(cash_release_i)
  - shortfall
```

年度激活数按公式直接累计，不除以 12。现金释放使用世界收款延迟；即使策略账期不变，收款状态仍可能改变现金占用。

## 5. 完全信息基准与遗憾

先枚举全部 2025 个策略及 27 个世界。对每个世界，只在该世界 `world_feasible=true` 的策略中取最大 `world_score` 作为完全信息基准；并列按后述策略键升序取第一。若某世界无可行策略，基准为零并记 `NO_FEASIBLE_ORACLE`。

每个策略在每个世界的遗憾为：

```text
regret = max(0, oracle_world_score-world_score)
```

不可行策略仍按其含短缺罚值的 `world_score` 计算遗憾，不能用空值或固定大数替代。

## 6. 概率指标

```text
feasible_probability = sum(probability where world_feasible)
expected_score = sum(probability * world_score)
expected_contribution = sum(probability * total_contribution_delta)
expected_cash_release = sum(probability * total_cash_release)
max_regret = max(regret)
```

`cvar90_shortfall` 是按 `shortfall` 从大到小排序后，最差 10% 概率质量的加权均值。跨过 10% 边界的世界只取所需概率质量；同短缺按 `world_id` 升序。若尾部概率质量不足，失败关闭。

## 7. 策略键、目录与选择

策略键固定为：

```text
MICRO={fee},{term};GROWTH={fee},{term};ENTERPRISE={fee},{term}
```

`fee` 与 `term` 使用不带小数的有符号整数，分群顺序不得按字典序改变。策略目录按策略键升序输出：

```text
policy_key,micro_fee,micro_term,growth_fee,growth_term,enterprise_fee,enterprise_term,feasible_probability,cvar90_shortfall,max_regret,expected_score,expected_contribution,expected_cash_release,action_magnitude
```

`action_magnitude = sum(abs(fee_delta_i)+abs(term_delta_i)/15)`。

严格按以下顺序选择唯一策略，比较使用未舍入值及 `comparison_tolerance`：

1. `feasible_probability` 最大。
2. `cvar90_shortfall` 最小。
3. `max_regret` 最小。
4. `expected_score` 最大。
5. `expected_cash_release` 最大。
6. `action_magnitude` 最小。
7. `policy_key` 升序。

`portfolio_decision.json` 至少包含选中键、上述六项指标、27 个世界的完全信息策略键、无可行基准世界、选择顺序和 `execution_status`。只要 `release_decision.json` 不是 `PROCEED`，`execution_status=ANALYTICAL_ONLY`；否则为 `READY`。
