# 运行与交付接口

## 1. 命令行

```text
python pricing_value_service.py run --input-dir INPUT --output-dir OUTPUT --business-cutoff 2026-06-30T23:59:59+08:00 --knowledge-cutoff 2026-07-08T12:00:00+08:00
python pricing_value_service.py validate --input-dir INPUT --work-dir WORK
python pricing_value_service.py explain --output-dir OUTPUT --segment SEGMENT
```

`run` 必须从输入重新计算全部结果；`validate` 必须逐项执行 `12_验收变化.csv`；`explain` 返回指定分群的证据计数、识别状态、入选动作和首个阻断原因。缺少输入、非法枚举、奇异矩阵、未完成观察窗或输出目录不可写时，以非零码退出，不得保留看似成功的旧结果。

## 2. 可见版本

所有事件时间均带时区。记录只有在 `effective_at <= business_cutoff` 且 `received_at <= knowledge_cutoff` 时可见。先按 `logical_id` 分组，再按 `(revision, received_at, event_id)` 升序取最后一条。最后一条 `operation` 为 `VOID` 时，该逻辑对象不存在。未列入规则的重复行不得凭文件顺序决定结果。

机会主档同样受 `source_revision` 控制；同一 `opportunity_id` 取最高修订，若并列按 `source_received_at`、`source_row_id` 取最后一条。

## 3. 纳入与归属

试验估计只纳入满足控制表“样本口径”的记录。家庭键去重在其他筛选之后执行：同一 `household_id` 只保留最早合格时间，时间并列取较小 `opportunity_id`。分组、波次和账户组均以机会主档的最终可见版本为准。

分配必须在首个有效报价前已接收且分配状态有效。报价取合格后 72 小时内首个有效逻辑报价；报价修订改变该逻辑报价本身，不产生新报价。净费率按控制表定义计算。

## 4. 漏斗与观察窗

漏斗事件先恢复逻辑版本，再按阶段取最早有效时间。阶段必须满足控制表规定的先后、时限和取消边界。重试键仅用于识别重复传送，不产生新阶段。未激活记录的 30 日交易量为零；已激活记录只汇总观察窗内最终状态为 `SETTLED` 或 `REFUND` 的交易逻辑对象。观察窗未在业务截止前闭合的记录保留在漏斗统计中，但不得进入弹性估计。

`funnel_summary.csv` 主键为 `(segment, wave)`，字段顺序：

```text
segment,wave,qualified,quoted,accepted,kyc_passed,activated,accepted_rate,activated_rate,complete_30d
```

## 5. 识别与区间

按分群独立估计。控制变量、工具变量、两个内生变量、两个结果变量、第一阶段 F、聚类协方差、有限样本修正和重采样参数均在控制表定义。分类控制项必须使用全局排序后的基准水平；某分群内不存在的水平不建空列。重采样单位是 `account_group`，抽中组后保留该组全部行，并为重复抽中的组创建独立簇标签。

`instrument_diagnostics.csv` 主键为 `(segment,endogenous)`：

```text
segment,endogenous,n,clusters,excluded_incomplete,first_stage_f,rank,status
```

`elasticity_results.csv` 主键为 `(segment,outcome,term)`：

```text
segment,outcome,term,estimate,cluster_se,ci_low,ci_high,bootstrap_success,status
```

任何内生变量的第一阶段 F 低于门槛、矩阵秩不足、有效簇不足或成功重采样次数不足，整个分群的因果状态为 `INSUFFICIENT`。点估计仍可保留用于解释，但不得据此改变费率或账期。

## 6. 贡献利润

交易、账单和贷项均先恢复逻辑版本。试验期实际贡献利润、基准贡献利润和四项差额使用控制表的定义。桥接必须严格满足：

```text
actual_contribution - baseline_contribution
= price_effect + volume_effect + activation_cost_effect + credit_effect
```

`profit_bridge.csv` 主键为 `segment`：

```text
segment,eligible,activated,actual_tpv,actual_net_revenue,actual_contribution,baseline_contribution,price_effect,volume_effect,activation_cost_effect,credit_effect,gap,reconciliation
```

## 7. 应收与 DSO

发票、贷项和回款按最终可见状态恢复。回款按发票号累计，贷项减少应收与收入；不得把商户结算款或交易退款当成服务费回款。DSO 使用控制表的滚动收入口径。负应收按零计入 DSO，但原始异常必须在 `release_decision.json` 的阻断码中保留。

`working_capital.csv` 主键为 `segment`：

```text
segment,invoiced_90d,credits_90d,cash_applied,open_ar,dso_days,overdue_ar,selected_term_days,annual_fee_revenue,cash_release
```

## 8. 候选动作

逐分群枚举控制表允许的费率变化和账期变化。预测、下行情形、转化约束、现金释放和批准边界按控制表计算。因果状态不足时仅允许零变化。`policy_frontier.csv` 保留全部候选及首个失败原因，不得只输出可行项：

```text
segment,fee_delta_bps,term_delta_days,predicted_conversion,predicted_annual_tpv,annual_contribution_delta,downside_contribution_delta,cash_release,feasible,first_failure
```

`selected_actions.csv` 主键为 `segment`：

```text
segment,fee_delta_bps,term_delta_days,predicted_conversion,annual_contribution_delta,downside_contribution_delta,cash_release,action
```

同一分群候选严格按控制表“选择顺序”比较，浮点比较使用控制表容差；不得用输出前四舍五入值比较。

## 9. 行动跟踪

按 `09_价值行动.csv` 的观察窗、分群和试验臂复核实际执行幅度、样本数、每个合格商机贡献和 DSO。状态必须逐项遵守登记表门槛，缺少对照或观察窗未闭合时不得显示已实现。

`initiative_tracking.csv` 主键为 `initiative_id`：

```text
initiative_id,segment,eligible_treatment,eligible_control,observed_fee_delta_bps,conversion_delta,contribution_per_eligible_delta,dso_delta,status,reason
```

## 10. 决策与清单

`release_decision.json` 至少包含 `business_cutoff`、`knowledge_cutoff`、`causal_status_by_segment`、`selected_action_keys`、`total_annual_contribution_delta`、`total_cash_release`、`overall_decision`、`blocking_codes`。只要任何分群发生数据完整性阻断，整体为 `HOLD_DATA`；只有证据充足且所有入选动作通过边界时才可为 `PROCEED`。

`run_manifest.json` 包含程序版本、规范化参数、全部输入文件 SHA-256、全部输出文件 SHA-256、行数、排序键和变化验收结果。散列文件列表按相对路径排序；清单不得包含自身散列、临时路径、主机名或运行时间。

## 11. 确定性与隔离

相同输入和参数重复运行必须逐字节一致。随机数种子从控制表读取，并按 `segment/outcome` 固定派生；不得使用进程全局随机状态。两个输出目录并发运行不得共享缓存、当前目录文件、环境变量状态或中间文件。
