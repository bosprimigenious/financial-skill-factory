# 临分封板规则

## 0. 认证帧

六个 `.pfr` 分片由连续帧组成。固定头为大端：`magic[4]="PFR1"`、`payload_len:uint32`、`sequence:uint64`、`logical_ms:int64`、`key_epoch:uint16`、`event_type:uint8`、`flags:uint8`，共 28 字节；随后是 `payload_len` 字节 UTF-8 JSON 与 32 字节 HMAC-SHA256。MAC 输入为固定头和原始 payload 的连接，密钥按 `key_epoch` 从 `17_认证密钥.json` 取得。

payload 必须是对象，原始字节须等于键排序、紧凑分隔符、禁止 NaN、禁止 ASCII 转义的规范 JSON。必须含 `record_id,kind,received_at`；头部 `logical_ms` 必须等于 `received_at` 的 Unix 毫秒，`event_type` 与 `kind` 按运行参数对应，flags 必须为 0。单帧 payload 不得超过参数上限。

每个分片内帧按 `(logical_ms,sequence,offset)` 严格递增；分片之间无顺序保证。程序须用六个单帧迭代器和最小堆归并为 `(logical_ms,sequence,shard_name,offset)` 全局顺序，不能整批载入。仅文件名最大的分片允许不完整尾部，且残留不得超过参数上限；该尾部忽略并入接收清单。其他截断、错误 magic、未知密钥期、错误 MAC、无效 UTF-8、非规范 JSON、头体不一致或分片内逆序均整批失败关闭。

接收账以 `record_id` 唯一。规范 payload 完全相同的重试只保留全局首次位置；同一编号出现不同 payload 时，全部版本写入冲突表，所有版本指向的份额及其申请隔离为 `CONFLICTING_RECORD_ID`。不得依赖相邻帧发现重试或冲突。所有完整帧先验证，水位后的记录验证后不参与该水位计算。

## 1. 双时间视图

水位视图仅纳入 `received_at <= evidence_cutoff` 的记录。申请、份额、授权、签章、先决条件和汇率还须满足自身业务时间不晚于业务计量时点。ISO 8601 时间必须含时区。

父记录不存在、父记录晚于子记录接收、业务发生时间晚于接收时间、授权或签章早于其目标首次接收，均属非法因果输入，整次运行失败。失败时退出码 2，不发布可见世代；失败证据写入状态库。

对同一对象，从根事件沿父链恢复。撤回叶子令该分支不可用，但不删除其他分支；无效子记录不切断最近有效祖先。水位内若存在两个以上可用叶子，该对象隔离。`AMEND` 继承未明确改动的父字段。

申请只有一个可用叶子时为 `ACTIVE`；多个可用叶子时为 `QUARANTINE/MULTIPLE_ACTIVE_LEAVES`；存在撤回叶子且已无可用叶子时为 `WITHDRAWN/WITHDRAWN`。份额多个可用叶子时为 `QUARANTINE/MULTIPLE_ACTIVE_LEAVES`，`leaf_event_id` 用字典序竖线连接。其余份额对所有控制逐项求值：全部通过为 `ELIGIBLE`；否则为 `REJECTED`，`reason` 将下列适用码按字典序竖线连接：`APPLICATION_BLOCKED`、`CLAUSE_CONFLICT`、`MISSING_APPROVAL`、`MISSING_SIGNATURE`、`SELF_APPROVAL`、`SUBJECTIVITY_LATE`、`SUBJECTIVITY_MISSING`、`WRONG_ROLE`。实际签入后 `ELIGIBLE` 改为 `SIGNED`；超出目标的剩余可采信份额为 `EXCESS_NOT_USED`。

## 2. 可采信份额

份额叶子必须同时满足：

- 状态不是 `WITHDRAWN`；
- 对应申请存在且未隔离；
- 存在一条在水位内接收、业务时间有效、目标版本完全一致的授权；
- 授权角色为 `CUO` 或 `HEAD_OF_REINSURANCE`，且授权人与份额提交人不同；
- 存在目标版本完全一致的经纪签章；
- 份额的所有 `subjectivity_codes` 均有目标版本一致、在 `due_at` 之前业务完成且在水位内接收的满足证据；
- 条款核验没有严重冲突。

申请与份额的 `terms_code` 在条款卡中解析。以下五项分别核验：`basis`、`hours`、`anchor`、`territory`、`currency`。条款卡的 `equivalent_to` 只是拟议关系；仅当水位内存在目标条款、参照条款完全一致的法务批准，批准角色为 `LEGAL_COUNSEL`，批准人与条款起草人不同，且五个核心字段仅存在 `wording_style` 差异时，才允许视为等价。任何其他差异均为严重冲突。未找到条款卡、拟议关系与批准目标不一致或等价链出现环，也属严重冲突。法务批准业务时间或接收时间早于目标条款首次进入材料的时间，属于非法因果输入。

`clause_findings.csv` 对每个份额叶子输出上述五项。值相同且条款编号相同写 `MATCH`；值相同、条款编号不同且符合等价规则写 `EQUIVALENT`；其余写 `CRITICAL`。严重冲突指任一行出现 `CRITICAL`。

## 3. 签入份额

按申请分别处理可采信份额。先按 `bind_priority` 升序，再按份额叶子的 `received_at` 升序，最后按 `line_id` 升序。每条签入比例为 `min(offer_share, target_share - 已签入, 该共同利益集团当期额度 - 该集团已签入)`；达到目标后，其余可采信份额记为 `EXCESS_NOT_USED`，仅受集团额度截断且仍有正签入的份额记为 `SIGNED_CAP_LIMITED`。部分签入必须保留原报价比例与实际签入比例。

份额归属由归属表给出。集团额度按事件父链恢复，水位内只能有一个有效叶子；多个有效叶子令使用该集团的所有份额隔离，不能改用较早额度。集团额度按申请分别占用，不跨申请相减。额度事件适用与申请、份额相同的双时间和因果规则。

申请建议：

- 实际签入比例达到 `target_share` 且正签入共同利益集团数不少于 `minimum_groups`：`BIND`；
- 未达目标但达到 `minimum_bind_share`，且正签入共同利益集团数不少于 `minimum_groups`：`BIND_WITH_GAP`；
- 未达到最低线：`HOLD`；
- 申请隔离：`QUARANTINE`。
- 申请已撤回：`NO_ACTION`。

只有 `BIND` 与 `BIND_WITH_GAP` 产生保费。任一被签入份额出现严重冲突时不得产生保费。

## 4. 保费

原币基础保费：`layer_limit * signed_share * rate_on_line`。

恢复保费准备金：`基础保费 * reinstatement_count * reinstatement_charge`。`reinstatement_count` 为整数；`reinstatement_charge` 为每次恢复相对基础保费的比例。

原币总额为二者之和。申请币种为 CNY 时汇率为 1；其他币种使用不晚于业务计量时点、且在水位内接收的最后一个官方定盘。相同 `currency`、`fixing_at` 若值不一致，整次运行失败。逐行先算未舍入值并折算人民币，最后按份额行四舍五入到分；申请汇总为已舍入份额行之和。

## 5. 状态文档与链

每个水位按输入顺序执行，不能自行按时间重排。状态文档为 UTF-8 JSON：对象键按字典序，数组按输出接口指定排序，紧凑分隔符，禁止 ASCII 转义。金额以两位小数字符串、比例以六位小数字符串写入。

`state_hash = sha256(state_document_bytes)`。

首节点 `chain_hash = sha256(("GENESIS|" + node_id + "|" + state_hash).encode("utf-8"))`；后续节点 `chain_hash = sha256((previous_chain_hash + "|" + node_id + "|" + state_hash).encode("utf-8"))`。

## 6. 失败关闭

输入字段缺失、枚举非法、数值越界、重复冲突、时间无时区、因果倒置、等价环、汇率冲突、W1 不早于 W2，均按第一节方式失败。不得留下半成品。

完整重放还须遵守 `15_事务续接协议.md`。
