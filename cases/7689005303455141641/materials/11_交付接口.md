# 运行与交付接口

运行：

`python 13_命令入口.py --input <材料目录> --output <空目录> --cutoff <OPEN|MID|CLOSE> [--state <state.json>]`

环境为 Python 3.13，只允许标准库。程序正常返回 0，生成 UTF-8 的 `settlement_report.jsonl`、`settlement_plan.jsonl`、`remediation_actions.jsonl`、`position_reconciliation.csv`、`state.json`、`manifest.json`。数组及行按主业务标识字典序排列，JSON 键顺序不限制。

`settlement_report.jsonl` 每条指令一行，至少包含：`instruction_id`、`trade_id`、`allocation_id`、`account`、`status`、`settled_quantity`、`settled_cash_cents`、`open_quantity`、`primary_reason`、`evidence_ids`。确定状态的已完成原因为 `NONE`；要素不一致原因为 `TRADE_MISMATCH`；路径不可用为 `SSI_INVALID`；其他原因使用规程中的大写名称。不确定原因使用 `EVIDENCE_CONFLICT`、`SOURCE_TIME_UNCERTAIN` 或 `ALLOCATION_AMBIGUOUS` 中最贴近的一个。

`remediation_actions.jsonl` 仅列未完成或不确定指令，至少包含：`instruction_id`、`action`、`open_quantity`、`preserve_final_quantity`、`evidence_ids`。`NEW_INSTRUCTION` 另含 `supersedes_instruction_id`；不得为已完成指令产生动作。

`settlement_plan.jsonl` 每个入选片段一行，至少包含：`window_id`、`unit_id`、`instruction_id`、`quantity`、`cash_cents`、`package_id`、`credit_draw_cents`、`collateral_ids`、`evidence_ids`。未入选指令不写占位行；同一额度的提款只在按片段标识最小的一行记载，避免重复合计。`package_id` 为包内片段标识排序后以 `+` 连接所得 SHA-256 前 16 位。

`position_reconciliation.csv` 固定表头：`account,isin,custody_account,expected_quantity,custody_quantity,difference,status,evidence_ids`。`evidence_ids` 使用 `|` 连接；不确定数字留空。只输出材料中存在开仓快照或托管余额的键。

`state.json` 必须包含足以从任意较早切点重放的原始事实、规范内容摘要和 `last_cutoff`。传入状态时，输入可能再次包含历史记录；重复投递不得改变结果。状态必须可由标准库 JSON 直接读取。

`manifest.json` 至少包含 `cutoff_id`、`report_count`、`plan_count`、`action_count`、`reconciliation_count`、`input_digest`、`output_digest`。摘要算法为 SHA-256：输入摘要对所有已解析输入业务文件按文件名，再按原始非空行字节排序后连接；输出摘要对除 `state.json`、`manifest.json` 外四个结果文件按文件名字典序连接完整字节。换行统一 `\n`。

公开检查只验证接口和一个基础链路，不代表完整验收范围。可以完全重写现行实现，但不得读取输出目录、参考文件或环境中的其他路径。
